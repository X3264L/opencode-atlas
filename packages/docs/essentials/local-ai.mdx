OpenCode can run coding agents against local models managed through [Ollama](https://ollama.com). Open `/local` in the TUI to see what your machine can run, install recommended quantizations, and switch to a local model.

## How recommendations work

OpenCode detects your hardware (GPU vendor and VRAM, system RAM, Apple unified memory) and scores every catalog model against it. Each model is evaluated per quantization variant (Q4_K_M, Q5_K_M, Q6_K, Q8_0 where the registry publishes them), and the best-scoring variant is highlighted as **★ Best for your PC**.

Scoring combines:

- **Fit** - whether the working set fits entirely in GPU memory
- **Quality** - higher-quality quantizations win when hardware supports them comfortably
- **Speed** - estimated smoothly from working-set size; every doubling of memory footprint costs a fixed number of points (no artificial thresholds)
- **Context** - practical context capacity on this machine, not theoretical maximum
- **Agent readiness** - measured OpenCode tool-calling performance when available

Presets (`overall`, `coding`, `agent`, `speed`, `memory`, `context`) reweight these factors.

## Working set estimates

The recommended context for each variant is the largest standard context step whose full working set (weights + KV cache + runtime overhead) fits inside the GPU budget minus a 12% safety reserve. Headroom shown in the UI is what remains at that context. These are conservative estimates; they are always labeled as estimated.

## Offload

When a working set exceeds safe VRAM, part runs in system memory:

| Offload level | Meaning |
| --- | --- |
| None | Fully GPU-resident |
| Partial | Up to 25% offloaded; noticeably slower |
| Heavy | Most layers offloaded; much slower |
| CPU dominant | No usable GPU detected |

Offloaded configurations are penalized heavily so a smaller model that fits usually outranks a larger one that spills.

## Estimated vs measured

Recommendations start from size-based estimates. After you run **Benchmark** on an installed model, real throughput measured on this machine replaces the estimate for that exact runtime tag (runtime + model + quantization). Slow measured performance lowers a recommendation; fast measurements raise it. Benchmarks are stored per variant - measuring Q4 does not affect Q6 or Q8 evaluations.

**Readiness** measures how well a model handles OpenCode agent tool calls and strongly influences agent-preset recommendations.

## Variants

Each catalog model lists its installable variants. The default variant uses the model's primary Ollama tag; other quants use Ollama's `-q6_K` / `-q8_0` suffix convention. Only variants listed in the UI are offered. If the registry does not publish a tag, the pull fails with Ollama's own error - nothing pretends to be installed that isn't.

## Downloads

Before installing, OpenCode checks free disk space on the Ollama models directory (honoring `OLLAMA_MODELS`). If space cannot be determined, the check is skipped rather than blocking you. Downloads stream progress into the TUI and can be cancelled mid-flight; cancelled jobs stop promptly and can be restarted anytime.

## Current limitations

- Install, benchmark, readiness, and cancellation require Ollama. LM Studio models are listed but not managed.
- Variant availability depends on what the Ollama registry publishes for each model.
- All pre-install numbers are estimates derived from parameter counts and public quantization profiles; only benchmark/readiness results are measured.
